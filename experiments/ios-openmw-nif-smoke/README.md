## Genuine parser architecture and dependency graph

The parser is `Nif::Reader` in `components/nif/niffile.hpp` and `niffile.cpp`. Its `parse(Files::IStreamPtr&&)` first computes the OpenMW internal file hash, checks the NetImmerse/Gamebryo header, reads version and record count, constructs typed records, reads roots and runs each record's `post` method to resolve references. `Nif::NIFFile` owns `mRecords`, `mRoots`, version and path; `Nif::FileView` exposes roots/version. The actual geometry data is in typed records: `NiNode::mChildren` in `node.hpp`, `NiGeometry::mData`, `NiTriShape` and `NiTriShapeData::mVertices`/`mTriangles` in `data.hpp`. Count vertices from the decoded `mVertices` vector and triangles from validated triples in `mTriangles`; check the declared triangle count and indices against those arrays. The parser does **not** construct `osg::Node` scene graph objects; `components/nifosg/nifloader.cpp` is the separate rendering conversion path.

The already proven D/E/F path provides `ESM::ESMReader`, `ESM::Static::load`, `OpenMWIOSBsaVfs::addExistingMorrowindBSA`, `VFS::Manager::buildIndex`, `exists` and `get`. The E library `openmw-ios-esm-vfs` can be reused unchanged. The F app's `DataProbe.cpp` currently enforces exact equality with its 24-byte non-NIF fixture, so that function cannot serve as the G0 parser input unchanged; an isolated G0 adapter must repeat or extract the proven ESM/BSA/VFS sequence and pass `manager.get(normalizedModelPath)` directly to `Nif::Reader::parse`. The F app, fixture and validators remain untouched. The VFS stream is a bounded input stream, and OpenMW's `niftest` demonstrates the same `reader.parse(vfs->get(...))` pattern.

The parser's source directory contains **12 `.cpp` translation units**: `base`, `controller`, `data`, `effect`, `extra`, `niffile`, `nifstream`, `node`, `particle`, `physics`, `property`, and `texture`. Their precise minimal link closure has not been established by a compiler/linker; `niffile.cpp`'s factory references many of these record types, so selecting only a header recognizer would not be genuine parser coverage. ## Fixture investigation

A recursive file inventory of this repository and the pinned OSG checkout found **zero `.nif`/`.NIF` files**. Existing `apps/components_tests/nifloader/testbulletnifloader.cpp` constructs in-memory NIF objects for tests; it does not provide serialized NIF bytes. Existing `apps/components_tests/nif/testphysics.cpp` writes a different Gamebryo-version test stream, not a validated Morrowind geometry fixture. The F `meshes/test.nif` resource is a 24-byte synthetic payload, not a valid demonstrated NIF. No proprietary game asset or downloaded model was used.

The OpenMW reader's source gives the relevant 4.0.0.2 contracts: version string, numeric version, record count, typed records, root indices, post-processing, and `NiNode`/`NiGeometry`/`NiTriShapeData` fields. It appears feasible to author a minimal original `NiNode` → `NiTriShape` → `NiTriShapeData` stream from those contracts, with no texture records. **Feasibility is not validity:** without the genuine parser compiling and accepting it, no bytes are being labeled a valid fixture, and there is no fixture size or SHA-256 to report. A deliberately invalid fixture should be derived after a parser-accepted positive fixture so rejection is meaningful.

## Resume conditions and proposed validation sequence

1. Supply or locate an offline C++20 host toolchain and verified Bullet headers/libraries for host testing, plus a defined offline route for iPhoneOS ARM64. Keep existing OpenMW/OSG pins. Audit the 12 NIF units and support sources for exact compile/link closure; resolve Bullet without modifying upstream. If this cannot be done, leave G0 blocked.
2. In this isolated directory, author a small original 4.0.0.2 NIF from the reader's contracts and document construction, provenance, byte size and SHA-256. Accept it as valid only after `Nif::Reader` parses it and typed records show a root, geometry, vertices and triangles. Create a corrupted/truncated negative fixture and test rejection. Do not use game assets or external textures.
3. Build a host G0 check using the unchanged D/E libraries plus the audited NIF closure. Generate a synthetic ESM `STAT` and BSA containing the authored NIF. Require genuine lookup, bounded VFS retrieval, exact SHA-256, `Reader::parse`, Morrowind version, resolved root/geometry relationship, nonzero decoded vertices and triangles, valid indices and unchanged inputs. Counts must come from parsed `NIFFile` records, never fixture metadata. Exercise wrong path, missing asset, corrupt bytes, invalid fixture and provenance mismatches as distinct failures.
4. Prepare a separate manual-only iPhoneOS ARM64/iOS 18.0 native build with independently checked source/OSG/Bullet provenance and dependency closure. If host success and dependency closure justify it, add an isolated unsigned UIKit evidence app and strict package validator modeled on F. Native CI should verify a genuine executable link and app link, bundle fixtures/metadata, package an unsigned IPA and mark physical runtime as unverified.
5. On a physical iPhone, require the exportable PASS/FAIL JSON/log to show the same fixture hashes, source/dependency revisions, actual parsed counts and negative-fixture rejection. A successful build, IPA or VFS lookup alone must not pass. Parsing success and geometry inspection remain distinct from rendering; G1/G2 work is outside G0.
